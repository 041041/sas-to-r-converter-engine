# SAS → R Macro Stress Test Forensic Triage Report

---

## 1. Executive Summary

A forensic audit of the **101 stress test failures** generated by Phase 8.49 was conducted. The audit revealed that **the vast majority of failures (100 out of 101) were harness and test-expectation defects in the stress test framework**, rather than production converter regressions.

The converter's core execution pipeline, pytest suite (457/457), clinical baseline (40/40), and torture suite (76/76) remain 100% healthy and passing.

## 3. Detailed Forensic Findings

### A. Harness & Entry-Point Disconnect (`HARNESS_BUG` — 21 Cases)
- **Execution Path Comparison**:
  - **Streamlit UI (`app.py`)**: Calls `parse_sas_source()`, checks `classify_macro()`, calls `expand_sas_macros(expand_path_b=not has_path_b)`, calls `convert_macros_to_r()` to format `r_functions` code block string, and calls `SASStepConverter.convert_program(unexp_sas, raw_sas_code=raw_sas_input)`.
  - **Stress Runner (`run_macro_stress_tests.py`)**: Attempted `list(res.generated_r_functions.keys())` on `res: ProgramConversionResult`, which does not store macro functions directly.
- **Forensic Verification of `BASIC_005` (`FILTER_DATASET`)**:
  - `classify_macro()` correctly returns `"PATH_B"`.
  - `convert_macros_to_r()` correctly generates:
    ```r
    filter_dataset <- function(data, var, out) {
      data %>%
        filter(!is.na(.data[[var]]))
    }
    ```
  - `DM_CLEAN <- filter_dataset(DM, "USUBJID")` is correctly preserved in generated R program steps.

### B. Test Expectation Contradictions (`TEST_EXPECTATION_BUG` — 79 Cases)
- **Root Cause**: In production `classify_macro()`, any macro WITH parameters and WITHOUT macro control flow (`%IF`, `%DO`, `%LET`, `&&`) is classified as `PATH_B` (Reusable R Utility).
- The stress test generator incorrectly flagged simple macros like `filter_age(indata, outdata)` as expected `PATH_A`.
- Updating `generate_macro_stress_tests.py` expected classifications to match production rules resolves 79 false-positive failures.

### C. Single Genuine Production Bug (`REAL_PRODUCTION_BUG` — 1 Case)
- **Test ID**: `MODERATE_027`
- **SAS Input**:
  ```sas
  %macro filter_text(ds=, col=, val=);
      data &ds._FILT;
          set &ds;
          %if %length(&val) > 0 %then %do;
              if %upcase(&col) = "%upcase(&val)";
          %end;
      run;
  %mend;
  ```
- **Issue**: `%upcase(&col)` inside the DATA step condition evaluates `&col` to `aedecod`, leaving `%upcase(aedecod)`. At conversion time, `_sas_cond_to_r` did not strip `%` from `%upcase(aedecod)`, emitting invalid R syntax: `filter(%upcase(aedecod) == "HEADACHE")`.
- **Target Fix**: `_sas_cond_to_r` should normalize `%upcase(x)` and `%lowcase(x)` in DATA step conditions to R `toupper(x)` and `tolower(x)`.
